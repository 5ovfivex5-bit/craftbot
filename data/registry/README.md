# data/registry (DATA-1, PROTOCOL 12.2)

Generated by `tools/registry/extract.py` (reads the Minecraft 26.2 jar + `mcsrc/`), checked by
`tools/registry/validate.py`. Regenerate with:

    .venv/bin/python tools/registry/extract.py && .venv/bin/python tools/registry/validate.py

Counts: 59 blocks (incl. 10 pseudo: agent + 9 mobs), 97 items, 65 recipes (57 crafting, 8 smelting),
9 mobs. Validation: OK (ids dense, v6 ids preserved, all recipe/drop/places_block/mob references resolve).

## Sources (per entry)

| Field | Source |
|---|---|
| recipes (result, count, ingredients, needs, cook_ticks) | jar `data/minecraft/recipe/<name>.json`; tags flattened via `data/minecraft/tags/item/**` |
| block drops (item, count, chance) | jar `data/minecraft/loot_table/blocks/<name>.json` (simplified, see below) |
| mob drops | jar `data/minecraft/loot_table/entities/<mob>.json` (simplified) |
| block tool tier (`best_tool`, `min_tier`) | jar tags `data/minecraft/tags/block/mineable/{pickaxe,axe,shovel,hoe}.json`, `needs_stone_tool`, `needs_iron_tool`, `needs_diamond_tool` |
| block hardness, `requiresCorrectToolForDrops` | `mcsrc/net/minecraft/world/level/block/Blocks.java` (`strength(h, r)`, `instabreak()`, helper properties, `ofLegacyCopy` / `registerLegacyStair` parents) |
| tool damage / speed / durability | `mcsrc/.../world/item/Items.java` (`pickaxe/sword/...(ToolMaterial.X, base, speed)`) + `ToolMaterial.java` (durability, speed, attack bonus) |
| food nutrition / saturation | `mcsrc/.../world/food/Foods.java` (saturation = nutrition * saturationModifier * 2, vanilla formula) |
| stack sizes | `Items.java` `stacksTo(n)`; default 64, tools/armor 1 |
| mob health / attack damage / speed | `createAttributes()` in `mcsrc/.../world/entity/{monster,animal}/...` (zombie inherits via Zombie.createAttributes; default health 20 when not declared) |

Anything not in those files is marked below as assumed.

## Choices and simplifications

- **Wood**: all wood collapsed to oak (`oak_log`, `oak_planks`, `oak_leaves`, slabs/stairs/fence/door/trapdoor). Tags such as `#planks` resolve to the first member present in our items (oak_planks).
- **Ids**: blocks 0..19 and items 0..14 are the v6 ids from PROTOCOL 12.2. Block 1 is named `grass` (v6 name, vanilla `grass_block`; the loot/recipe lookups use the vanilla name). Mob pseudo-blocks are ids 20..28 (zombie, skeleton, spider, creeper, cow, pig, sheep, chicken, zombified_piglin), matching the CORE seed. Remaining blocks and items are appended in a fixed order.
- **Deepslate**: `deepslate` (17) is the generic stone-below-y8 block. Deepslate ores are separate blocks (`deepslate_coal_ore`, `deepslate_iron_ore`, `deepslate_diamond_ore`, `deepslate_gold_ore`) with the same drops as their surface ores (from the copy in Blocks.java; loot tables give the same drop items).
- **Ores**: `iron_ore`/`deepslate_iron_ore` drop `raw_iron`, `gold_ore` drops `raw_gold`, `nether_quartz_ore` drops `quartz`, coal drops `coal`. Fortune and silk touch are ignored (the default-branch drop is kept). Lapis, copper, redstone, nether gold and emerald are out of scope.
- **Smelting ore items**: the jar's ore-smelting recipes take ore *items* (`iron_ore`, `gold_ore`, ...). Ore block items are out of scope, so these are mapped to the raw item (`iron_ore` -> `raw_iron`, `gold_ore` -> `raw_gold`). Smelting raw_iron/raw_gold is the same recipe in practice.
- **Recipes**: canonical `<result>.json` or `<result>_from_*.json` (e.g. `white_wool_from_string`). Each (result, input) pair appears once. `needs` = `inventory` when the pattern fits 2x2 (or shapeless with <= 4 ingredients), otherwise `crafting_table`. Smelting, campfire cooking and smoking are all treated as `furnace` (`cook_ticks` from the jar). Blasting is not used. Recipes not in the jar (e.g. `water_bucket`, `string`, `bone`) are absent; they come from the world or mobs.
- **Crafting recipes have `cook_ticks: 0`** (CORE seed convention). `name` is the jar recipe file name.
- **Block simplifications**: beds (`white_bed`), doors (`oak_door`) and the wheat crop are single blocks (vanilla is two-part / multi-stage). `white_wool` is the only wool colour. Stairs/slabs are single blocks with the parent's hardness.
- **Drops** (`loot_table` simplified): first surviving alternative per pool, silk-touch and shears-only branches dropped, `table_bonus` (fortune) uses its base chance (e.g. leaves -> stick 2%, apple 0.5%; gravel -> flint 14%). `requires_tool_tier` = block `min_tier` if the block has `requiresCorrectToolForDrops`, else 0. Drops whose item is not in items.json are removed: `oak_leaves` -> oak_sapling, `wheat` -> wheat_seeds, zombie -> red_mushroom/carrot/potato/music disc, spider -> spider_eye, zombified_piglin -> gold_nugget.
- **Tool damage**: `tool.damage` is the melee damage the player deals (1 + item base + material bonus, matching in-game display: wood sword 4, diamond sword 7, iron axe 9). `tool.speed` is the material's mining speed, `tool.durability` the material's durability.
- **Tiers**: `tool.tier` / `min_tier` use 0 hand, 1 wood, 2 stone, 3 iron, 4 diamond. Gold tools are not in scope (gold tier is a wood-tier tool).
- **Spears**: not included (out of scope; `copper_spear` is present in 26.2 data).
- **Food `saturation`** = nutrition * saturationModifier * 2 (vanilla saturation points, not the raw modifier).
- **Armor**: armor items have `kind: "armor"` and `tool: null`. The armor stats are an extension key `armor: {slot, defense, durability}` on armor items only. Defense and durability values are assumed (vanilla).
- **Mob `attack`** for passive mobs is `"none"` (CORE seed convention; 12.2's list did not include it). Creeper uses `"explode"` with `damage: 0`. `pseudo_block_id` is an extension key with the block id (matches the blocks.json entry).
- **Leather armor and leather** are included (cheap, drops from cows).
- **Mob ghast/blaze** are not included (optional, need blaze_rod / ghast_tear items). The nether mob is zombified_piglin only.

## Assumed (not in the jar or mcsrc files; hand-set in extract.py)

- **Block physical properties** (`solid`, `transparent`, `liquid`, `light_emission`, `color`, `dimension`) for all blocks. These are hand-set and approximate.
- **Block hardness fallbacks** for the entries the parser could not read: `white_wool` 0.8 and `white_bed` 0.2 (declared via ColorCollection). `wheat` 0.0 and `air` 0.0 are also hand-set. `water` and `lava` use 100.0 (source value via strength), `bedrock` -1.0 (source).
- **Fuel ticks** (`fuel_ticks`), vanilla values (coal 1600, planks/logs 300, wooden tools 200, ...).
- **Item `value`** (MineRL-style shaping, 2^depth by tech depth) is hand-set.
- **Armor** defense/durability (see above).
- **Mob size** (`size`), **attack type**, **spawn** (`light_max`, `day`, `group_min/max`, `dimension`) and `burns_in_sun` are hand-set (vanilla-like, aligned with the CORE seed).
- **Mob health/damage/speed** are from mcsrc where declared (`createAttributes`). Cow health 10 and speed 0.2 are assumed (`Cow.java` declares no attributes in mcsrc).

## Schema notes

- `blocks.json`: fields as 12.2, plus `pseudo` (true for agent and mob pseudo-blocks). Pseudo-blocks have `hardness: 0`, no drops.
- `items.json`: fields as 12.2, plus `armor` on armor items.
- `recipes.json`: `{id, name, result, count, ingredients{item: n}, needs, cook_ticks}`.
- `mobs.json`: fields as 12.2, plus `pseudo_block_id`. `pseudo_block` is the block name.

Known gaps: `mcsrc/` is a partial decompile, so `EntityType.java` does not declare mob sizes; sizes are assumed. Mob spawn data is not in the jar's data packs, so spawn fields are assumed.
